### Pre-existing bug found during verification — NOT from this build

`GET /api/bom/archetypes` returns **HTTP 500** in the `MApper demo (synthetic
data)` project:

```
2 validation errors for ArchetypeSummary
stage_ids.Manufacturing  Input should be a valid string [input_value=None]
stage_ids.Use Phase      Input should be a valid string [input_value=None]
```

- **Reproduces identically on the installed `beaeda3` build**, so it is not this
  build's regression.
- Cause: `summarize_archetype` builds `stage_ids = {r.name: r.id for r in
  arc.bom}` and `ArchetypeSummary.stage_ids` is `dict[str, str]`, but both
  **seeded** demo archetypes (`demo-icev.json`, `demo-bev.json`) have stage roots
  with `id: null`. `assign_ids_to_roots` runs on the create route, not on load,
  so seeded/persisted archetypes never get them.
- Effect: the Archetypes list cannot load in that project — on any install,
  since the demo project ships this way. `v014-demo-check` lists fine.
- Verification worked around it by fetching `GET /bom/archetypes/demo-icev`
  directly. **Not fixed here; reported for a decision.**
