## DMG step failed: Finder not answering AppleScript

`tauri build --target aarch64-apple-darwin` compiled Rust (32 s) and bundled
`MApper.app`, then failed in `bundle_dmg.sh`:

```
createdmg.tmp…:394:406: execution error: Finder got an error: AppleEvent timed out. (-1712)
failed to bundle project: error running bundle_dmg.sh
```

That line is create-dmg's AppleScript that lays out the DMG window in Finder.
It failed identically on a second attempt, and a one-line probe
(`tell application "Finder" to get name of startup disk`, 15–20 s timeout) also
timed out, twice, minutes apart. So **Finder itself is not answering Apple
Events** on this machine: either Finder is hung, or an Automation permission
prompt ("… wants to control Finder") is waiting on screen.

- It is **not** the stale-path Cargo failure from #162, so `cargo clean` was not
  run.
- Each failed attempt left a ~1.4 GB `rw.*.dmg` scratch image in
  `bundle/macos/`; both were deleted. No volume was left mounted.
- The `.app` is complete before the DMG step starts and the DMG only packages
  it, so the `.app` was verified and installed. **To produce the DMG:** get
  Finder answering (approve the prompt, or relaunch Finder), then re-run
  `tauri build --target aarch64-apple-darwin`; the Rust and the freeze are
  cached, so it is the DMG step again and nothing else.
